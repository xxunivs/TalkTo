# 외부 5인 전체 흐름 검증 (전사 → 화자 식별 → 클론)

## 목적

가족(신금자) 데이터가 아닌 외부 페르소나 5명으로 전사, 화자 식별, 클론 전 구간이 사람이 바뀌어도 작동하는지(일반화) 확인한다. 참조 클립 없는 내용기반 폴백과 참조 클립을 주는 ECAPA 성문 매칭(제품 주 경로)을 함께 돌려 비교한다.

## 방법

1. 데이터: 외부 페르소나 5명(최영자, 정말순, 이순덕, 김분남, 서정숙) 통화 wav, 페르소나당 최대 4건.
2. 파이프라인: Scribe 전사와 화자분리 → 대상자 화자 식별 → 대상자 구간 수집(통화별) → 누적 풀 → IVC 클론(voiceId) → TTS 한 줄 합성.
3. 두 경로 비교. 경로 A는 참조 없이 전사문 호칭으로 LLM이 판정하는 내용기반 폴백, 경로 B는 사용자가 짚은 목소리 구간을 참조로 쓰는 ECAPA 성문 매칭.
4. 참조 클립(경로 B)은 실제 UX의 사용자 짚기를 대신해, 통화 내 한 화자가 가장 길게 말한 구간 20초를 자동 선정했다. 노인 면담 데이터라 피면담자가 대상자이고, 면담자(collector)는 페르소나 간 공유되지만 유사도로 확실히 갈린다.
5. 임계값 0.5. 생성된 voiceId는 확인 후 전부 삭제했다.

내용기반 폴백은 전사문에 대상자를 부르는 호칭이나 이름이 실제로 등장할 때만 라벨을 반환하고 없으면 기권한다. 이 데이터셋 통화들은 짧은 문답이 많고 가족 호칭이 없어, 규칙대로 대부분 기권했다. 코드 결함이 아니라 호칭 근거가 없어서 안 찍은 것이다.

## 결론

1. 5명 전부, 전체 통화 18건 전부가 경로 B로 매칭에 성공했고 클론과 TTS까지 완결됐다. 참조 클립이 있으면 호칭이 없는 통화도 다 붙는다.
2. 성문 마진이 크다. 대상자 본인은 0.838~1.0, 다른 화자는 0.165~0.391로 그 사이 간격이 최소 0.45 이상이라 임계값 0.5에서 오분류 없이 갈렸다.
3. diarization 라벨은 통화마다 독립이라 최영자와 서정숙은 통화별 대상자 라벨이 뒤바뀌는데, 성문이 라벨과 무관하게 같은 목소리를 매 통화에서 짚어 통화 간 신원 일관성을 유지했다.
4. 클론 엔진은 가족이 아닌 외부 인물 목소리에도 일반화돼 작동한다. 누적 풀에서 상한 180초로 선별해 한 목소리로 학습했다.
5. 내용기반 폴백은 호칭이 있는 통화에서만 보조로 동작하므로, 대상자 식별의 신뢰 경로는 사용자 짚기 기반 ECAPA다.
