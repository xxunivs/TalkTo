# PART 0. 설계 원칙과 답변 형식 규격 (기획·개발 공유용)

## 0-1. 세그먼트가 아니라 축(axis)으로 판별한다

| 축 | 값 | 결정되는 것 |
|---|---|---|
| **A. 답변 주체** | 본인(1인칭) / 타인·가족(3인칭) / 혼합 | 문형(나는~ / 그분은~), 검수 주체(본인 / 작성 가족), 출처 기본값 |
| **B. 대상자 상태** | 대화 가능(생존·소통 가능) / 대화 불가(사별) / 소통 어려움(법률 검토 전 잠금) | 시제(현재/과거), 목소리 원천(신규 녹음 / 보유 자료), 동의 경로(본인 낭독 / 가족 동의+증빙), 사별 관련 문항 노출 순서·M9 기본값 |
| **C. 시점** | 지금 이 모습 / 특정 시기 | 페르소나의 지식 범위·기억 필터 |

- 축 A는 묻지 않는다. PART 1의 관계 답(본인/타인)에서 자동 결정된다. 축 B·C는 PART 1에서 값만 받는다.
- 기존 세그먼트는 조합의 별칭이다: 사별 유족 = 타인·불가·과거 / 시니어 본인 기록 = 본인·가능·지금 / 치매 가족·어린 자녀 = **법률 검토 전 실사용 금지**.
- **하드 제약:** 동의 없는 타인 페르소나 제작 불가 / 대화 불가 대상은 가족 동의+관계 증빙+가족 검수 게이트 필수(동의 이중 경로).

## 0-2. 3층 수집 구조 — "빠른 v0 후 성장"

| 층 | 무엇 | 시점 | 분량 |
|---|---|---|---|
| **L1 Core** | PART 1 관계 설정 + PART 2 필수 8문항 + M9 최소 1회 (+ 사별이면 T1-01·T1-02) | 음성 업로드 직후, v0 생성 전 | 5~10분 |
| **L2 성장 질문** | PART 3 모듈 문항을 "오늘의 질문" 카드로 분산 + 세션 종료 아웃오브캐릭터 결손 질문 | v0 생성 후 | 하루 1~3문항 |
| **L3 보완 인터뷰** | PART 4 타겟 모듈 + 데이터 현황에서 부족 영역 집중 세션(Premium은 직원 진행) | 품질 미달 시 / Premium 착수 | 영역별 10~20분 |

- 모든 서술형 답변은 **음성 우선**(전사 → 기억 데이터, 본인 답변은 말투·음성 데이터 겸용), 텍스트 대체 허용. 객관식은 탭 입력.
- 대화 불가 대상(작성자=유족)의 노출 순서는 **감정 안전 순**(★1 → ★5). ★4·5는 건너뛰기 버튼을 항상 노출.
- 답변마다 종착지 표시: "이 답변은 페르소나의 ○○(말투/기억/금기)가 됩니다."

## 0-3. 앱 입력 플로우

```
음성 업로드 → 화자 확인(1탭) → PART 1 관계 설정(1분) → PART 2 Core 8문항 + M9 등급표(5~10분)
→ [본인] v0 미리보기 → 첫 대화 시 Memories 결제  /  [타인·고인] (사별: T1-01·02) → Family 결제 → v0 생성 → 가족 검수
→ L2 오늘의 질문(PART 3) + 세션 종료 결손 질문 2~3개
→ 데이터 현황: 모듈별 확보/부족 → 부족 영역 탭 → L3 진입
```

## 0-4. 답변 형식 코드 (전 문항 공통 — 앱 컴포넌트와 1:1)

| 코드 | 형식 | 규칙 |
|---|---|---|
| **[단일]** | 단일 선택 | 선지 중 하나만. 부연 입력 없음. "직접 입력"이 있는 문항만 자유 텍스트 1칸(30자) 허용 — 이 값은 파싱하지 않고 "기타: …"로 그대로 프롬프트에 들어간다 |
| **[복수 n]** | 복수 선택 | 최대 n개. 선택 순서 = 우선순위로 저장 |
| **[단답 n]** | 짧은 텍스트 | n자 이내 1칸. 문장이 아니라 값(이름·지명·연도·표현 하나) |
| **[숫자]** | 숫자 | 연도·개수. 음력/양력 같은 보조 선택은 문항에 명시 |
| **[서술]** | 자유 서술(음성 권장) | **반드시 답변 가이드 동반**(무엇을 / 몇 문장 / 예시). 상한 표기. 앱은 가이드를 질문 아래 회색 글씨로 노출 |
| **[표]** | 1행 1항목 반복 입력 | 열 정의 고정. "행 추가" 버튼. 최소·최대 행 수 표기. **한 칸에 여러 개 나열 금지.** 각 행은 독립 레코드 — 행마다 `source`·`status`(0-6)를 가진다(예: 거주 이력 한 행만 "확인 필요") |
| **[등급]** | 주제별 4등급 선택 | M9 전용(0-6 참조) |
| **[확인]** | 예 / 아니요 | 절차 확인용 |

## 0-5. 답이 가는 곳 (분류)

| 분류 | 의미 |
|---|---|
| **A 프롬프트** | system prompt에 직접 들어가 모든 대화에 항상 적용. **★ = A 중 없으면 v0를 만들 수 없는 필수** |
| **B 기억** | 기억 DB(RAG)에 저장, 대화 주제가 닿을 때만 검색 |
| **C 운영** | 프롬프트·기억 어디에도 안 들어감(절차·권한·알림 설정) |

## 0-6. 공통 메타 필드 — 값 안에 대괄호 메모를 쓰지 않는다

모든 답변 레코드에 아래 필드가 붙는다. `[추정]`, `[확인 필요]`, `[추가 녹음 필요]` 같은 표시는 값 안에 쓰지 않고 이 필드로 표현한다.

| 필드 | 값 | 비고 |
|---|---|---|
| `source` 출처 | 본인 / 직접 들음·목격 / 가족 전언 / 그랬을 것 같음(추정) | 축 A=본인이면 자동 "본인". 타인 작성 시 서술·표 문항마다 선택 필수. **추정은 검수 통과 전 단정 발화에 쓰지 않는다** |
| `status` 상태 | 답함 / 건너뜀 / 모름 / 확인 필요 | "모름"은 **발화 금지 영역**으로 프롬프트에 전달("그 주제는 자료가 없다"). "확인 필요"는 값을 저장하되 검수 큐에 적재 |
| `ai_scope` 사용 범위 | 자유 / 물으면만 / 회상 참고만(발화 금지) | ★3 이상 문항과 M5·M7 카드에 노출. 기본값 "자유" |
| `sensitivity` 민감도 | 낮음 / 중간 / 높음 | 문항 기본값 ★에서 자동, 사용자가 올릴 수 있음 |
| `answered_by` | 작성자 ID | 가족 여러 명이 작성 가능 |

**M9 등급 4단 (0-4 [등급]):** ① **자유** — 페르소나가 먼저 꺼내도 됨 / ② **물으면만** — 먼저 꺼내지 않고, 물으면 답함 / ③ **짧게 넘김** — 물어도 한두 마디로 받고 화제를 돌림 / ④ **금지** — 답하지 않고 정해진 문구로 안내. **모든 등급에 "단서" 칸(60자)이 붙는다** — 예: 가격 = 자유 + 단서 "출시 가격 기준, 조정될 수 있음을 함께 말한다".

**시스템 고정 가드레일(질문하지 않음, 전 페르소나 상수):** "기억 안 나" 발화 금지("그건 내가 잘 모르겠다" 계열만) / AI 정체를 흐리는 발화 금지 / 자료에 없는 사실 지어내기 금지 / 의료·치료·효능·부활·영혼 표현 금지 / 유사도 단정 금지 / 화자 본인의 임종·사망 경위를 **먼저 꺼내지 않음**(축 B=사별 기본 — 사용자가 꺼내면 T1-02 범위 안에서 답한다). 이 항목들은 **입력받지 않는다.**

## 0-7. 문항 표기 규칙

`ID` · **분류(A★/A/B/C)** · [형식] · ★n 감정 안전 순위(1 안전 ~ 5 민감) · → 반영처(말투/기억/관계/금기/절차). 질문의 대괄호 = 치환 슬롯: [나는/그분은] 형태로 앱이 축 A·B에 따라 자동 치환. 3인칭 작성 시 시제도 축 B로 치환(대화 가능=현재, 불가=과거).

## 0-8. 작성본(답안지) 표기 규격 — 시험지와 답을 한 장에

작성본 파일(`페르소나 테스트/Persona_Intake_○○.md`)은 본 문서의 문항을 **그대로 옮기고 그 아래에 답**을 적는다. 답만 따로 적지 않는다.

- 객관식: 선지를 전부 나열하고 선택한 것만 **■**, 나머지 □. 부연은 "메모" 줄에만(프롬프트 미반영).
- 단답·서술: `답:` 줄에 값. 서술은 가이드의 문장 수 안에서.
- 표: 열 그대로 표로. 행마다 출처·상태.
- 모든 문항 끝에 `[출처: 본인|직접|전언|추정] [상태: 답함|건너뜀|모름|확인 필요]`. 상태가 "답함"이 아니면 답 칸은 비운다 — 값 안에 "확인 필요"라고 쓰지 않는다.
- 답이 없는 문항도 생략하지 않고 상태만 적는다 → PART 5-3 결손 목록이 여기서 자동 생성된다.

# PART 1. 관계 설정 (L1 — 1분)

| ID | 분류 | 형식 | 질문 | 선지 / 가이드 | 비고 |
|---|---|---|---|---|---|
| **P1-01** | A★ | [단답 20] | 페르소나로 남길 분의 이름은요? | 예: 신금자 / 이준혁 | 생년·고향은 여기에 쓰지 않는다(M1-01) |
| **P1-02** | A★ | [단일] | 그분은 나에게 어떤 분인가요? — "그분은 나의 ___" | 본인(나 자신) / 어머니 / 아버지 / 할머니 / 할아버지 / 외할머니 / 외할아버지 / 배우자 / 아들 / 딸 / 형·오빠 / 누나·언니 / 남동생 / 여동생 / 친구 / 스승 / 직접 입력 | **방향 고정: 대상자 → 나.** "손자"처럼 나→대상자 방향 답은 앱이 받지 않는다. 본인 선택 시 축 A=1인칭, P1-03 이하 문형이 "나는~"으로 바뀜 |
| **P1-03** | A★ | [단답 15] | 내가 그분을 부르는 호칭은요? | 예: 할머니 / 엄마 / 아빠 / 여보 / (이름) | 본인이면 건너뜀. 페르소나가 자기 자신을 가리키는 1인칭 호칭으로 쓰인다("할머니는~") |
| **P1-04** | A★ | [단일] | 그분과 지금 대화할 수 있나요? | 예, 대화할 수 있어요 / 아니요, 돌아가셨어요 / 아니요, 대화가 어려우세요(치매 등) | 축 B. 여기서는 값만 받는다. 사망 시점·경위·마지막 시기의 가족 상황은 **T1-01·T1-02**에서 따로 받는다(페르소나가 자기 일을 알아야 "임종 때 곁에 못 있어서 죄송해요" 같은 말에 답할 수 있다). 셋째 선택 시 안내 후 잠금(법률 검토 전). 본인이면 자동 "예" |
| **P1-05** | A★ | [단일]+[단답 30] | 어느 때의 모습을 남기고 싶나요? | ① 지금 이 모습 / ② 특정 시기 → 시기 입력(예: "2015년쯤" / "분당 살던 말년" / "칠순 무렵") | 축 C. **P1-04=사별이면 ①은 비활성**, ②의 시기 입력 위에 프리셋 "돌아가시기 전 건강하시던 시절"을 제공. 이유("왜 이 시점인가요?")는 별도 [서술] 선택 문항 P1-05b(★2, B) — 프롬프트에 넣지 않음 |
| **P1-06** | A★ | [단답 15] | 페르소나가 **나를** 뭐라고 불러야 하나요? | 예: 준혁이 / 우리 딸 / 종서야 / ○○님 | **작성자 1인분만.** 다른 가족의 호칭은 M2 관계 카드에서 1인 1행으로 받는다. 본인 페르소나가 불특정 방문자를 상대하면 "○○님" 같은 기본 호칭 |
| **P1-07** | C | [표] 0~3행 | (타인 작성 시) 함께 답해주실 분이 있나요? | 열: 이름(단답) / 그분과의 관계(P1-02 선지) / 역할(주 작성자·보조) | 출처 태그와 검수 초대에 쓰임. 프롬프트 미반영 |

**PART 1에서 뺀 것:** "함께 쓸 가족"(초대 목록 → 앱 F 구역 가족·플랜 화면, C 운영) / "접근 범위"(→ M9-02) / "가족 동의 현황"(→ PART 5 절차 상태, 동의서 세트가 원본). Intake 질문이 아니라 상태값이다.

# PART 2. L1 Core — 필수 8문항 (v0 생성 조건)

*말투 객관식 4 + 성격·애정 2 + 시그니처 표현 1 + 가드레일 1. 문형은 축 A로 치환: [나는/그분은].*

### C1 · A★ · [단일] · ★1 · → 말투(응답 길이)
**[나는/그분은] 말할 때 보통 어느 정도 길이로 말[해요/하셨어요]?**
- ① 한두 문장으로 짧게
- ② 서너 문장 정도
- ③ 그보다 길게, 예를 들어가며 자세히
> "짧게/보통/길게"는 사람마다 기준이 달라 문장 수로 묻는다.

### C2 · A★ · [단일] · ★1 · → 말투(응답 방식)
**[나는/그분은] 이야기할 때 주로 어떤 식[이에요/이셨어요]?**

### C3 · A★ · [단일] · ★1 · → 말투(정서 반응)

- ② 담담하게 끝까지 들어준다
- ③ 말없이 곁에 있어준다
- ④ 짧은 한마디로 안심시킨다 (예: "잘될 거야")
- ⑤ 직접 입력

### C4 · A★ · [복수 2] · ★1 · → 말투(조언 스타일)

- ② 무조건 내 편을 들어준다

# PART 5. 검수·절차·결손 (C 운영 — 페르소나에 들어가지 않음)

## 5-1. 검수 체크리스트 — 항목별 [확인] 예/아니요, 하나라도 "아니요"면 해당 문항으로 이동

**본인 검수(축 A=본인):** 나답게 느껴진다 / 내가 안 할 말이 없다 / 남기고 싶지 않은 이야기가 들어가지 않았다 / 대화 범위(M9-02)가 맞다 / 금지 주제(M9-01)를 지정했다.

**가족 검수(축 A=타인, 특히 대화 불가):** 그분답게 느껴진다 / 호칭·관계에 오류가 없다 / 추정 답변이 실제 발화처럼 쓰이지 않았다 / 이 페르소나로 상처받을 가족이 없다 / 모르는 걸 아는 척하지 않는다 / 먼저 꺼내면 안 되는 주제가 지정됐다 / 접근 권한을 가족이 합의했다. **대화 불가 대상은 가족 검수 통과 없이 완성되지 않는다.**

## 5-2. 절차 상태(시스템 기록, 질문 아님)

동의서 01~04 확인·동의 여부 / 별지 A(본인 낭독) 또는 별지 B(가족 동의+증빙) 상태 / 목소리 게이트(대상자 발화 분량) / 결제 티어(Memories·Family) / 검수 통과일.

## 5-3. 결손 목록(시스템 자동 생성 — 손으로 관리하지 않는다)

`status`가 답함이 아닌 필수·권장 문항을 앱이 모아 데이터 현황 화면과 세션 종료 결손 질문의 큐로 쓴다. 상태별 처리:

| 상태 | 처리 |
|---|---|
| 미수집(빈칸) | 오늘의 질문·결손 질문으로 노출 |
| 확인 필요 | 검수자에게 "맞나요?" 카드 |
| 대상자에게 물어볼 것(대화 가능) | T3 링크로 발송 |
| 모름(수집 불가) | 발화 금지 영역으로 프롬프트에 전달, 재질문 안 함 |

> 손으로 관리하는 잔여 수집 목록은 이 큐가 대체한다.
