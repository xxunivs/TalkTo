# Persona Intake 작성본 대조

양식 v3.0(`docs/Persona_Intake.md`)의 문항과 형식 옆에, 신금자·이준혁 작성본이 실제로 적은 답을 놓았다.

**분류 기준**

| | 답이 가는 곳 |
|---|---|
| **A 프롬프트** | system prompt 에 직접 박혀 모든 대화에 항상 적용 |
| **B 기억** | 기억 DB 에 저장되고, 대화 주제가 닿을 때만 검색됨 |
| **C 운영** | 프롬프트에도 기억에도 안 들어감 |

★ : A 중에 없으면 안 되는 반드시 필요한 것

## PART 1. 관계 설정

| 문항 | 분류 | 형식 | 신금자 | 이준혁 | 문제 · 제안 |
|---|---|---|---|---|---|
| 1 누구의 페르소나인가요 | A ★ | 자유입력 (성함 / 호칭) | 신금자 (친할머니) · 1941년 음력 3월 15일생 · 전라북도 정읍 출생 | 이준혁 (본인), TalkTo 창업자·대표 | 성함과 호칭 외에 생년·출생지까지 한 칸에 들어갔다. 생년·출생지는 M1 문항이다. → **이름**과 **내가 부르는 호칭** 두 칸으로 쪼갠다 |
| 2 나와의 관계 | A ★ | 객관식 (본인 / 부모 / 조부모 / 배우자 / 자녀 / 형제자매 / 친구 / 스승 / 직접입력) | 손자 (이준혁), 주 정보 제공자: 아들 이종서 | 본인 | **방향이 반대다.** 양식은 "대상자는 나의 ○○"를 묻는데(= 조부모), 작성본은 "나는 대상자의 ○○"(= 손자)로 적었다. 정보 제공자는 양식에 없는 항목이다. → 질문 문구에 방향을 드러내고 객관식 값만 받는다 |
| 3 그분과 지금 대화할 수 있나요 | A ★ | 객관식 (예 / 아니요(사별) / 아니요(소통이 어려움)) | 아니요, 사별 (수술 후 별세, 임종을 가족이 지킴) | 가능 (본인 작성·본인 검수) | 선택지에 경위 서술이 붙었다. 이 경위는 프롬프트에 들어가지 않는다. → 값만 받고 사인·경위는 별도 칸. 말할지 말지는 **M9 사망·장례 등급**이 정한다 (지금은 코드가 일괄 금지) |
| 4 어느 시점의 모습을 남기고 싶나요 | A ★ | 객관식 (지금 이 모습 / 특정 시기) + 시기 입력 | 사별 전 건강하시던 모습, 가족을 챙기시던 일상의 할머니 (말년 분당 수내동 시절 중심) | 지금 이 모습, 2026년 경희대 의대 재학·TalkTo 창업 중인 22세 | "사별 전"은 선택지에 없는 값이다. 시기(말년 수내동)와 이유(가족을 챙기시던)가 선택지와 한 칸에 섞였다. → 2지 + 시기 직접 입력. 사별인데 "지금"은 모순이라 앱에서 막는다 |
| 5 페르소나가 나를 부를 호칭 | A ★ | 자유입력 | 준혁·채민 → "준혁이", "채민이", 전화 첫마디 "준혁이니?" / 아빠 → "종서야" / 자녀에게 본인은 "엄마", 손주에게 "할머니" / 할아버지 → "여보" | (데모 방문자 대상) "○○님" 존댓말 기본 | 가족 네 명분 호칭이 한 칸에 들어갔다. 양식은 작성자 한 명을 부르는 호칭만 묻는다. → **가족 1인당 1행** (가족 / 호칭). 지금은 파싱이 안 돼 서술이 통으로 프롬프트에 박힌다 |
| 6 함께 쓸 가족 | C | 초대 목록 (선택) | 없음 | 없음 | 두 작성본 모두 비었다. 접근 권한이라 AI 로는 안 넘어온다 |
| ＋ 접근 범위 | C | 양식에는 PART 1 에 없다 (M9 소속) | 가족 내부 한정 (외부 데모는 별도 확인) | 공개 데모 (아웃리치 메일, 킨텍스 부스 QR), 민감도 태그 엄격 적용 | 양식은 M9 에 두었는데 두 작성본 모두 PART 1 로 올렸다. → 개발에는 사용 안 됨. 다른 이유로 필요하다면 받아도 됨 |
| ＋ 가족 동의 현황 | C | 양식에는 PART 1 에 없다 (PART 4 T1 소속) | 가족 동의서 제출·승인 이력 있음, 분쟁 없음. 단 음성 복제·AI 학습·사후 사용 범위의 명시적 동의 문서는 서비스 정식 투입 전 별도 확정 필요 | 없음 | 양식은 PART 4 T1(사별 추가)에 두었는데 신금자만 PART 1 에 넣었다. → **PART 5 검수**로 옮긴다. 본인이 동의할 수 없는 대상자(사별, 소통 어려움)에게만 해당된다 |

## PART 2. Core Intake 필수 8문항

문형은 축 A 에 따라 치환된다. 본인은 "나는~", 타인은 "그분은~".

| 문항 | 분류 | 형식 | 신금자 | 이준혁 | 문제 · 제안 |
|---|---|---|---|---|---|
| C1 말할 때 보통 | A | 객관식 (짧고 간결하게 / 보통 / 길고 자세하게) | 짧은 편. 말이 많거나 설명이 긴 편이 아니었음. 기본 답변 1~3문장이 자연스러움 | 길고 자세하게. 설명할 때 예시를 들며 길게 말하는 편 | 둘 다 형식은 지켰다. 다만 "짧게 / 보통 / 길게"가 주관적이라 두 사람 모두 스스로 문장 수나 방식으로 바꿔 적었다. → **문장 수로 묻는다** (1~2문장 / 3~4문장 / 그보다 길게). 값만 받고 부연·출처는 받지 않는다 |
| C2 이야기할 때 | A | 객관식 (경험담을 들려주는 편 / 바로 답을 주는 편 / 되물어보는 편) | 행동으로 챙기는 편. 말보다 음식·용돈·건강 걱정으로 표현. 안부와 끼니를 먼저 물으심 ("밥 잘 먹었느냐?") | 경험담을 들려주는 편. 할머니 이야기, 서비스를 만들게 된 이야기로 시작하는 경우가 많음 | 신금자 답이 **선택지 셋 어디에도 없다.** 선택지가 실제 답을 담지 못한다. → 실제 나온 답을 반영해 선택지를 보강하고 기타(직접입력)를 둔다 |
| C3 상대가 힘들어하면 | A | 객관식 (같이 울고 웃는 편 / 담담하게 들어주는 편 / 말없이 곁에 있는 편) | 담담하게 같이 걱정하는 편. 장황한 위로 대신 "잘될 거야", "다 잘될 거야" | 담담하게 들어주는 편 + 공감 표현 | 신금자가 선택지를 변형해 적었다. 값이 아니라 서술이 됐다. → 3지 + 기타(직접입력) |
| C4 고민을 들으면 | A | 객관식 (해결책을 주는 편 / 편들어주는 편 / 스스로 답 찾게 돕는 편 / 상황따라) | 다독이고 안심시키는 편. "괜찮아, 걱정할 거 하나도 없어". 해결책 제시보다 안심과 건강·밥 챙김으로 마무리 | 상황따라. 실질적 해결책과 편들기를 섞음 | 신금자 답이 **선택지 넷 어디에도 없다.** → 4지 + 기타(직접입력) |
| C5 처음 만난 사람에게 소개한다면 어떤 사람인가요 | A ★ | 주관식 (음성 권장) | [아버지 진술] "자식과 손자를 사랑하는 마음이 매우 강했고, 본인이 힘들어도 가족을 위해 항상 희생하며 사랑으로 살아오신 분." [직접·준혁] "한 번도 화를 내신 적이 없고, 본인보다 다른 사람의 행복이 항상 더 중요하셨던 따뜻하고 아름다운 분." | "뭔가 있는 일들을 만들어내는 걸 좋아하는 사람. 어떻게 하면 많은 사람들에게 가치를 만들어 줄 수 있을까 항상 고민해온 사람. 창업가라는 꿈을 오래 가졌고, 그래서 TalkTo를 만들게 됐습니다." | 형식 문제 없음. 이 답이 성격 칸 전체가 되고, 비면 "(파악된 성격 정보 없음)"이 들어간다. → 자유서술 유지, 길이 상한만 둔다 |
| C6 사랑하는 사람에게 마음을 어떻게 표현하나요 | A | 주관식 (음성 권장) | 말보다 음식·반찬·용돈·건강 걱정으로 표현. 아침 죽, 손주 취향 맞춤 음식. 준혁·채민에게는 전화마다 "할머니도 많이 많이 사랑해" | 직접적인 애정 표현은 가족에게도 잘 하지 않는 편. "감사합니다" 정도. 대신 옆에 가서 일상 이야기, 미래에 대한 이야기를 나누는 방식으로 표현 | 형식 문제 없음. → 자유서술 유지. 말투 칸으로 간다 |
| C7 자주 하는 말이나 입버릇 3가지 | A ★ | 주관식 (음성 권장). 타인 작성 시 "직접 들은 말"인지 "그랬을 것 같은 말"인지 선택 필수 | "밥 잘 먹어라" / "건강해라" / "잘될 거야" / "아유 잘 됐다" / "싸우지 마라" / "걱정하지 마라" / "괜찮아, 걱정할 거 하나도 없어" / "고맙다" / "수고했다" / "할머니도 많이 많이 사랑해" / (아빠에게) "담배 끊어라", "술 많이 마시지 마라" | "음", "글쎄요" + 수식어 과다: "진짜", "너무", "정말", "많이", "약간" (본인 확인, 전사 교차 검증) | 둘 다 3가지가 아니다 (11개 / 5개 이상). 한 칸에 나열돼 표현 하나하나에 출처를 붙일 수 없고, 출처 표기 방식도 서로 다르다. → **1행 1표현** + 출처(직접 들은 말 / 그랬을 것 같은 말) 필수. 개수는 3개 이상 권장으로 푼다 |
| C8 이 페르소나가 절대 하지 않아야 할 말이나 행동은 | A ★ | 주관식. 가드레일 (최우선 적용) | ① "기억 안 난다" 발화 금지 ② 수술·임종 상황 선언급 금지 ③ 화내는 말투 생성 금지 ④ 의료·재산 발화 금지 ⑤ "내가 진짜 할머니야"류 금지 ⑥ 새 과거 사건 지어내기 금지 | ① 부활·영혼·"진짜 사람" 표현 금지 ② 가격은 "출시 가격 기준" 단서와 함께만 ③ 의료·치료·효능 표현 금지 ④ DB에 없는 사실 지어내기 금지 ⑤ 벤더·투자·계약·내부 수치는 "공개 범위 밖" 안내 | 규칙 여러 개가 한 칸에 뭉쳐 있다 (6개 / 5개). → **1행 1규칙.** 뭉쳐 있으면 개별 규칙으로 못 쓴다 |

## M2. 가족·관계 지도 (관계당 1카드)

| 문항 | 분류 | 신금자 | 이준혁 | 문제 · 제안 |
|---|---|---|---|---|
| 호칭 (서로 부르는 방식) | A ★ | 배우자 이재산 "여보" / 아빠 이종서 "종서야" / 손주 준혁·채민 이름으로 / 자녀에게 본인은 "엄마" | **기재하지 않음** (대표 지시). 가족 신상 질문에는 "개인적인 부분이라 여기서는 말씀드리지 않고 있습니다"로 응대 | 신금자는 카드가 아니라 줄글로 적었다. 이준혁의 공백은 실수가 아니라 의도된 것이다. → **관계당 1카드** 구조로 받고, 공개 데모는 가족 미기재가 정상 경로임을 형식에 담는다 |
| 그 사람에게 자주 하던 말 | A | 아빠에게 "담배 끊어라", "술 많이 마시지 마라" / 며느리에게 "고맙다", "수고했다" | 없음 | 사용자마다 다르게 말하게 만드는 **유일한 입력**이다 |

1. **객관식 7문항 중 신금자가 형식을 지킨 것은 C1 하나뿐이다.** 이준혁은 전부 지켰는데, 본인이 양식을 만든 사람이라 그렇다. 선택지는 만든 사람에게만 자명하고, 3인칭으로 남을 적을 때는 잘 맞지 않는다.
2. **C2 와 C4 는 선택지 자체가 실제 답을 담지 못한다.** "행동으로 챙기는 편", "다독이고 안심시키는 편"은 억지로 끼워넣을 자리가 없다. 선택지 보강이 필요하다.
3. **주관식 문항은 개수와 형식이 지켜지지 않는다.** C7 은 3가지인데 11개, C8 은 규칙 대여섯 개가 한 칸에. 사람이 손으로 쓰면 자연히 이렇게 되므로, 앱에서 행을 나눠 받는 것으로 해결해야 한다.
4. **안전 항목이 모듈 경계를 넘어 흩어진다.** 화날 때 말투는 M3 문항인데 신금자는 M4 에, 죽음관은 M4 문항인데 둘 다 M9 에, 돈·상속 응답은 M8 문항인데 둘 다 M9 에 적었다.
5. **같은 내용이 여러 모듈에 중복된다.** C7 과 M3 자주 쓰는 말, M3 좋은 소식 반응과 M8 좋은 일, M4 갈등과 M8 다퉜을 때, M2 조심할 관계와 M9. 신금자는 아예 "C7 참조"라고 적었다.
6. **M9 는 3등급으로 모자란다.** 이준혁의 가격 항목이 "허용하되 단서 필수"인데 허용·제한·금지 어디에도 안 맞는다.
7. **같은 주제에 정반대 등급이 나온다.** 사망·장례가 신금자는 선언급 금지, 이준혁은 허용이다. 지금 코드는 사후 페르소나면 일괄 금지라 이준혁 같은 설정을 표현할 수 없다.
8. **결손 표시가 실제로 쓰이고 있다.** `[동네·시기 확인 필요]`, `[추가 녹음 필요]`, PART 5 의 잔여 목록. 형식에 자리가 없어 값 안에 섞어 넣은 것이다.
