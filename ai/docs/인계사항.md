# TalkTo AI 인계사항 (2026-09-09)

## 1. 파이프라인 s1~s5

1. 구성은 s1 전사(a 전사 / b 화자 판별 / c 교정), s2 추출(a 인물 / b 민감도 / c 말투 / d 프롬프트 재료 합치기 / e 기억 / f 요약·태그), s3 합성(a 기억 모으기 / b 통찰 / c 프롬프트 조립 / d 임베딩), s4 음성, s5 대화입니다. 도구 이름과 산출물 이름을 맞췄습니다. `c_extract_linguistic_style.py` 가 `c_recording_linguistic_style.json` 을 내는 식입니다.
2. 실행은 `python -m pipeline.run_pipeline --subject <이름>` 이고 `--only s2`, `--only s2_e`, `--from s2 --to s3` 로 구간만 돌릴 수 있습니다. s4·s5 는 STEP_ORDER 에 없어 따로 호출합니다. 대화는 `python -m pipeline.s5_chat.a_chat --subject <이름>` 입니다.
3. 기능이 바뀌면서 구조가 달라진 부분을 반영해 코드 정리는 끝냈고, 단계별로 한 번씩 돌려보며 점검하는 일이 남았습니다. 화자 판별(s1_b), 기억 추출(s2_e), 프롬프트 조립(s3_c) 순으로 보면 됩니다.
4. 같은 단계 순서가 `infra/be_ai_api/recording_analysis.py` 에도 있습니다. 순서를 바꾸면 두 곳을 같이 고쳐야 합니다.
5. 전사는 `a_transcript.json` 에 이미 있는 녹음을 건너뜁니다. 다시 돌려도 유료 API 를 부르지 않습니다.
6. 입력과 산출물이 갈려 있습니다. 사람이 넣는 자료는 `input/<대상자>/`(음성/, Persona Intake 작성본 docx·md, persona_intake.json, 인터뷰 전사·기억DB 같은 손 자료), 단계별 결과는 `output/<대상자>/` 입니다. 파이프라인이 자동으로 읽는 것은 persona_intake.json 과 음성/ 뿐입니다. 매뉴얼 페르소나는 같은 입력을 쓰고 산출물만 `output/<대상자>_manual/` 로 갈립니다.
7. 녹음이 없거나 적은 사용자를 위해 s1 을 건너뛰고 인테이크만으로 s2·s3 를 돌리는 경로가 필요합니다. 지금은 s1 결과가 없으면 뒤 단계가 멈춥니다. 이준혁이 그 경우입니다.

## 2. 배포

8. 한 레포에 두 서비스가 있습니다. `talkto-app-ai` 는 앱용 파이프라인(Docker, autoDeploy false)이고, `talkto-persona-ai` 는 신금자 프로토타입(rootDir `manual_persona/신금자`)입니다.
9. `talkto-app-ai` 는 수동 배포라 라이브 이미지가 오래됐습니다. 1번 점검이 끝나면 재배포해야 합니다.
10. 두 서비스가 제 개인 Render 계정에 있습니다. 톡투 팀 계정으로 옮겨야 하고, 이전하려면 팀 워크스페이스에 결제 수단이 먼저 등록돼야 합니다.

## 3. 백엔드 분리

11. BE 가 프로토타입과 앱용을 같이 참조합니다. `AI_SERVER_URL` 은 `talkto-app-ai` 를 가리키는데, `MEMORY_IMPORT_SOURCE_URL` 은 구 프로토타입 레포(`TalkTo_PersonaAI_AI`)의 파일을 그대로 읽고 있습니다.
12. 참조를 앱용으로 분리한 뒤 재배포가 필요합니다.
13. BE 레포 접근 권한은 아직 받지 못했습니다. 수연님 회신 대기 중입니다.

## 4. Persona Intake 보강

14. 통화녹음이 적은 사용자도 페르소나를 만들 수 있도록 설문을 보강했습니다. 지금 99문항입니다.
15. 빈 양식은 `docs/Persona_Intake.docx` 와 그 소스 `docs/Persona_Intake.md`, 굽는 스크립트는 `docs/tool_Persona_Intake/`, 용도와 필수 분류는 `docs/Persona_Intake_문항분류.md` 입니다. 작성본 docx·md 는 `input/<이름>/` 에 있습니다.
16. 최근 바뀐 것은 출처 네 선지를 `실제로 들은 말은 아니에요` 체크 하나로 통일한 것, M2-01 가족 표에 `그분이 자기를 부르는 말` 과 `그분이 이 사람에게 하는 말투` 열을 넣은 것, M3-07(말끝)과 M8-11(먼저 자주 물으시던 말)을 새로 만든 것입니다.
17. 준혁님께 다시 받을 곳은 세 군데입니다. M2-01 의 새 두 칸, M3-07, M8-11 입니다.
18. 문항 확정과 수집 시점은 준혁님·기획팀이 정하기로 했습니다. 처음에 다 받으면 피로해서 필수만 먼저 받고 나머지는 천천히 받는 방향입니다.

## 5. 수집 유저플로우

19. 녹음과 사용자 답변이 같은 필드를 채웁니다. 내부 필드는 `persona_intake.json` 입니다. 지금 코드는 설문(`b_intake_prompt.json`)과 전사(`d_recording_prompt.json`)를 각각 만든 뒤 s3_c 에서 합치고, 같은 칸에 둘 다 있으면 설문이 이깁니다. 사용자에게 확인받는 절차는 아직 없습니다.
20. 녹음이 있으면 먼저 전사·분석해서 나온 값을 필드에 넣습니다. 녹음이 얼마나 커버하는지는 사람마다 달라서, 채워진 항목과 빈 항목이 사용자마다 다릅니다.
21. ★ 문항을 사용자에게 받되, 녹음으로 채워진 항목은 이 내용이 맞는지 확인과 수정을 받고, 빈 항목은 새로 묻습니다.
22. ★가 다 차면 페르소나 생성을 시작합니다. 사용자가 확인한 값만 프롬프트에 들어갑니다.
23. 나머지 문항을 언제 어떻게 받을지는 기획팀이 정합니다.

## 6. 문항 분류

24. 용도는 A(시스템 프롬프트) / B(기억DB) / C(둘 다 아님)이고, ★는 없으면 생성이 안 되는 문항입니다.
25. 지금 99문항 기준으로 A 43, B 38, A와 B 둘 다 8, C 10 이고 ★는 30 입니다.
26. ★ 없이 A 인 문항도 있으면 있을수록 답변이 좋아집니다. 세부 중요도는 기획팀이 문항을 보며 정하는 쪽으로 넘겼습니다.

## 7. 정해졌지만 아직 구현 안 된 것

27. 추정 발화 처리 규칙입니다. 실제로 하신 말만 발화 예시로 그대로 인용하고, 추정으로 표시된 말은 인용하지 않고 그 상황에서 어떤 방향으로 답할지를 정하는 데만 씁니다.
28. `pipeline/s3_synthesis/b_persona.py` 는 지금 출처를 전혀 쓰지 않고 예시를 그대로 넣습니다. 예시를 넣을 때 출처로 거르고 추정은 지침 문장으로 바꾸는 작업이 필요합니다.
29. 전사 분석 결과를 어느 문항에 채울지의 대응표가 필요합니다. `s2_extraction/d_merge_recording_prompt.py` 가 recurringPhrases 를 감탄사로, addressTerms 를 가족 호칭으로, sensitivityFlags 를 금기 후보로 옮기는 데까지는 했습니다. 남은 것은 sentencePatterns·emotionalExpressions 를 C-01·C-02·C-07·M8 계열 중 어디에 넣을지입니다.
