# Persona Intake 문항 분류

## 표기

- **용도** A = 시스템 프롬프트에 들어감 / B = 기억DB에 들어감 / C = 프롬프트에도 기억에도 안 들어감
- **★** 제작 시 처음부터 있어야 하는 문항. 없으면 대화하면서 천천히 채워도 되는 문항
- 조건부 문항(P1-07A·B·D, T1-02)의 ★는 그 경우에 해당할 때만 필수라는 뜻

## 수집 흐름

- 녹음과 사용자 답변(Persona Intake)이 같은 필드를 채운다 (내부 필드 `persona_intake.json`)

1. 녹음이 있으면 먼저 수집받아 전사·분석해서 나온 값을 필드에 넣는다
2. ★(꼭 있어야 하는 문항)을 사용자에게 받되, 녹음으로 채워진 건 확인과 수정을 받고 빈 건 새로 묻는다
3. ★가 다 차면 페르소나 생성 시작
4. 나머지 문항은 프롬프트에 들어갈 것과 기억DB에 들어갈 것으로 나눈다. 금기는 들어오는 즉시 반영하고, 나머지는 모아서 반영한다. 수집 방법은 기획 후 결정

- 웹앱(2026-10-17): 만들 때 ★ 대부분(P1-05·C-04·C-06·M3-07·M8-03·M8-08·M8-11·M9-01·M9-03)과 사실 둘(M1-02 고향·M1-07 하신 일)을 선택 질문으로 묻는다. 꼭 답할 것은 기본 정보와 C-01·C-02·C-05·M4-01 넷뿐이고, T1-02(건강, 동의 필요)는 다 만든 뒤 '질문 더 답하기'에서 묻는다
