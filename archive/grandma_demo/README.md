# TalkTo Persona AI

TalkTo 사후 Phase — 할머니 페르소나 AI 챗봇의 AI 파트

## 환경 세팅

### 1. 레포 클론
```bash
git clone https://github.com/xxunivs/PersonaAI.git
cd PersonaAI
```

### 2. Python 가상환경 생성
```bash
python3.11 -m venv venv
source venv/bin/activate
pip install openai python-dotenv
```

### 3. .env 파일 생성
프로젝트 루트에 `.env` 파일을 만들고 API 키를 넣어주세요.
```
OPENAI_API_KEY=여기에_API_키_입력
```
※ API 키는 팀원에게 개별 전달받으세요. .env 파일은 GitHub에 올라가지 않습니다.

### 4. 테스트 실행
```bash
source venv/bin/activate
python stage1_test_api.py
```
GPT 응답이 출력되면 환경 세팅 완료!

## 개발 단계

### Stage 1: API 연결 확인 ✅
GPT한테 "안녕" 보내고 응답이 오는지 확인.
API가 연결되는지만 보는 단계.

확인: 응답이 정상적으로 오면 성공.

---

### Stage 2: 전사본 분석 (임시)
할머니 통화 전사본(1,425줄)을 읽으면서 할머니가 어떤 사람인지 파악.

- 말투 패턴 정리 (사투리, 자주 쓰는 표현, 문장 끝 처리)
- 성격/감정 패턴 (걱정, 칭찬, 관심 표현 방식)
- 사실 정보 추출 (가족관계, 요리법, 경험, 가치관)
- 6대 차원 분석 (언어 / 심리 / 관계 / 가치관 / 기억 소환 / 논리 추론)

확인: 할머니의 말투, 성격, 기억을 문서로 정리 완료.

---

### Stage 3: 프롬프팅 vs 파인튜닝 비교
GPT한테 "할머니처럼 말해"를 두 가지 방식으로 시켜보고 비교.

**방법 A — 프롬프팅**
시스템 프롬프트에 "전라도 사투리 쓰고, 손자 걱정하고, 이런 말투로 답해" 라고 지시.
Stage 2에서 분석한 말투/성격을 프롬프트에 넣음.

**방법 B — 파인튜닝**
전사본 대화 데이터를 GPT에 학습시킴.
OpenAI Fine-tuning API로 실행, 학습 완료 후 모델 ID 발급.

같은 질문 여러 개 던져보고 어느 쪽이 더 할머니다운지 비교.
→ 결과에 따라 프롬프팅만 쓸지, 파인튜닝도 쓸지 결정.

확인: 두 방식의 답변을 비교하고 방향 결정.

---

### Stage 4: 페르소나 프로필 작성
할머니의 인격 설정 파일(JSON)을 만드는 단계.

- metadata: 이름, 나이, 관계
- personality: 핵심 성격 특성
- system_prompt: 기본 프롬프트 + 행동 가이드라인 + 말투 예시
- memories: 장기 기억 배열 (Stage 5에서 채움)

확인: 4개 블록(metadata, personality, system_prompt, memories) 완성.

---

### Stage 5: 장기 기억 구축
전사본에서 할머니의 기억을 뽑아서 검색 가능하게 만드는 단계.

#### 5-1. 기억 chunk 작성
전사본 + 가족 정보에서 기억을 하나씩 정리.
예: "불고기 양념은 간장 한 숟가락 반, 매실청 조금"
각 chunk에 id, category, title, content, importance 부여.

#### 5-2. 임베딩 생성
각 기억을 벡터(숫자 배열)로 변환. (text-embedding-3-small)
나중에 사용자 질문과 비교해서 관련 기억을 찾을 수 있게 함.

#### 5-3. 재임베딩 스크립트
기억을 추가하거나 수정하면 해당 chunk만 다시 임베딩하는 도구.

#### 5-4. 지식 그래프 (KG) 구축 — HippoRAG 적용
기억 속 인물/장소/사건을 노드로 만들고 관계를 연결.
예: 할머니 → 막내아들 이종서 → 손자 이준혁 → 경희대 의예과
NetworkX + spaCy NER로 구축.
검색 시 Personalized PageRank(PPR)로 관련 기억을 따라감.

확인: 가족 관련 질문 10개에 대해 기대 기억이 검색 top-5 안에 들어옴.

---

### Stage 6: 단기 기억 인프라
대화하면서 새로 알게 된 정보를 자동으로 저장하는 시스템.
(예: "준혁이가 오늘 직장 스트레스 있다고 함")

#### 6-1. 단기 기억 스키마 정의
각 기억에 다음 필드:
- content, category, importance (1~10)
- strength (강도, 기본값 1.0) — MemoryBank 논문 적용
- recall_count (회상 횟수)
- last_recalled_at (마지막 회상 시각)
- archived (망각되었는지)

#### 6-2. 추출 임계값
importance 6 이상인 것만 저장 (테스트하면서 조정).

확인: 단기 기억 스키마가 정의되고 저장/조회가 동작함.

---

### Stage 7: RAG 검색 파이프라인
사용자가 질문하면 관련 기억을 자동으로 찾아오는 시스템.

#### 7-1. 장기 기억 검색
임베딩 유사도 검색 + KG(PPR) 검색을 합쳐서 사용.
(하이브리드 검색: 임베딩 70% + KG 30%)

#### 7-2. 단기 기억 검색 — Generative Agents 적용
세 가지 점수를 합산해서 순위 매김:
- Relevance (관련성): 질문과 얼마나 관련?
- Recency (최근성): 최근 기억일수록 높은 점수
- Importance (중요도): 중요한 기억일수록 높은 점수

#### 7-3. 결과 통합
장기 기억 top-3 + 단기 기억 top-2를 합쳐서 프롬프트에 넣음.
장기 기억이 단기보다 우선 (사실 충돌 시 장기 기억 신뢰).

#### 7-4. RAG 캐시
같은 질문이 45초 안에 또 오면 다시 검색 안 하고 캐시 사용.

#### 7-5. 회상 시 강도 갱신 — MemoryBank 적용
단기 기억이 검색 결과에 포함되면 strength +1 (자주 회상되는 기억은 강해짐).

확인: 같은 질문에 일관된 결과, 핵심 기억 누락 없음.

---

### Stage 8: 프롬프트 빌더
GPT에게 보내는 프롬프트를 자동으로 조립하는 모듈.

조립 순서:
1. 시스템 프롬프트 (인격, 말투, 행동 가이드라인)
2. 장기 기억 섹션 (우선)
3. 단기 기억 섹션
4. 최근 대화 히스토리 6턴 (토큰 예산 관리)
5. 답변 지침 (1~2문장, 모르면 지어내지 말 것)
6. 감정 톤 프롬프트 (Stage 12에서 활성화)

확인: 프롬프트가 올바르게 조립되고 토큰 한도를 넘지 않음.

---

### Stage 9: LLM 응답 생성 + 품질 보정
프롬프트를 GPT(또는 파인튜닝 모델)에 보내서 답변을 받고, 품질을 체크.

- 단답 방지: "어", "응" 같은 너무 짧은 답 → 다시 생성
- 반복 방지: 최근 5개 답변과 비교해서 너무 비슷하면 (Jaccard ≥ 0.6) → 다시 생성
- 할루시네이션 회피: 검색된 기억이 약하면 "글쎄, 그건 잘 모르겠네" 식으로 회피

확인: end-to-end 테스트 — 질문 → 기억 검색 → 프롬프트 조립 → 답변 생성 → 할머니다운 답변.

---

### Stage 10: 음성 처리 (STT/TTS)
텍스트 대화를 음성으로 확장.

#### 10-1. STT (음성→텍스트)
사용자가 Push-to-talk으로 말하면 Whisper API가 텍스트로 변환.
잡음 필터링 포함.

#### 10-2. TTS (텍스트→음성)
GPT가 생성한 텍스트 답변을 ElevenLabs로 할머니 목소리로 변환.
이미 클로닝된 voice_id 사용.

#### 10-3. voice-first 흐름 (PersonaAI_Spec v0.2.1)
Push-to-talk 입력 → STT → 답변 생성 → 할머니 음성 먼저 재생 → 재생 끝나면 텍스트 표시.

#### 10-4. fallback
TTS 실패 → 텍스트 답변만 표시.
STT 실패 → "다시 말씀해주세요".

#### 10-5. 보안
생성된 음성 다운로드 금지 (signed URL 짧은 만료).

확인: end-to-end 음성 대화 평균 ~6초 이내.

---

### Stage 11: 백그라운드 단기 기억 추출
매 대화 턴마다 자동으로 중요한 정보를 단기 기억에 저장.

#### 흐름 (매 assistant 답변 직후):
1. ImportanceEvaluator: 5차원 중요도 평가 (감정 30%, 관계 25%, 개인정보 15%, 기억가치 20%, 연속성 10%)
   - GPT 보조 모델 + 휴리스틱 하이브리드, 일일 100회 제한 (비용 통제)
2. importance ≥ 6이면 →
3. EnhancedMemorySummarizer: 요약 생성 (제목, 내용, 인사이트, 감정톤)
4. 임베딩 생성
5. 단기 기억 DB에 추가
6. (선택) Reflection: 단기 기억 50개 이상 누적 시 메타 인사이트 생성 — MVP에서는 비활성화

확인: 대화 1주 후 단기 기억에 실제 사건이 저장되어 있고, 다음 대화에서 회상됨.

---

### Stage 12: 감정 엔진
사용자의 감정을 파악해서 할머니 톤을 조절.

- EmotionDetector: 한국어 키워드 기반 감정 추론 (9가지: happy, sad, worried 등)
- EmotionTracker: EMA(지수이동평균)로 감정 안정화 (갑자기 왔다갔다 안 하게)
- ToneMapper: 감정에 따라 LLM 프롬프트 톤 + ElevenLabs TTS 설정 조절
  (슬플 때 → 따뜻한 위로 톤, 기쁠 때 → 밝은 톤)

확인: 슬픈 메시지에 위로, 기쁜 메시지에 칭찬으로 답하는지 테스트.

---

### Stage 13: 운영/모니터링
MVP 출시 후 품질을 추적하고 개선하는 시스템.

#### 13-1. 사용 이벤트 저장
usage_events: ptt_pressed, voice_play_started, text_revealed 등.

#### 13-2. 오류 로그 저장
error_logs: STT/TTS/LLM/RAG 오류를 provider별로 분리 저장.

#### 13-3. 피드백 분류
- "사실이 틀렸어요", "기억에 없는 말을 지어냈어요" → 기억 보강 큐
- "섬뜩하거나 불편했어요" → 윤리/UX 검토 큐

#### 13-4. 기억 보강 사이클
부정 피드백 → 대표가 가족과 통화 → 장기 기억 수정 → 재임베딩 → 재테스트.

#### 13-5. 단기 기억 망각 배치 (일 1회) — MemoryBank 적용
14일간 한 번도 회상 안 된 기억은 강도가 자연 감쇠.
강도 0.1 미만이면 archived 처리 (잊혀짐).

#### 13-6. 개발자 통계 페이지 데이터 API
통계 카드, 피드백 테이블, 부정 피드백 큐, 오류 로그 조회.

확인: 부정 피드백 → 24시간 이내 보강 → 재테스트 시 개선 확인.

---

### Stage 14: 테스트 후 평가/조정
MVP 출시 2~3주 후 운영 데이터를 보고 결정.

1. Reflection 활성화 검토
   - 단기 기억 50개 이상? + "맥락 못 짚는다" 피드백? → 활성화
2. 검색 가중치 조정 (relevance, recency, importance 비율)
3. 추출 임계값 조정 (기억이 너무 적으면 5점으로, 너무 많으면 7점으로)
4. 장기/단기 우선순위 재검토 (충돌 사례 발생 시)

---
